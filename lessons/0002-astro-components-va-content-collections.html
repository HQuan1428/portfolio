Astro Component Model, Routing & Content Collections

Làm chủ cấu trúc file .astro, cơ chế Layout Slots, file-based routing và quản trị nội dung an toàn kiểu dữ liệu với Content Collections.

Mục tiêu kiểm soát Agent: Hiểu rõ cách Astro tổ chức dữ liệu giúp bạn đặt ra các "hàng rào bảo vệ" (constraints) rõ ràng, ngăn AI Agent tự ý tạo cấu trúc tùy tiện hoặc đưa thư viện ngoài vào quản lý dữ liệu.

1. Giải Phẫu Một File .astro

Một component Astro được chia thành hai phần rõ rệt bằng hàng rào --- (fence):

---
// 1. COMPONENT SCRIPT (Chạy 100% tại Build Time)
// Import các component khác, đọc dữ liệu, tính toán logic
import BaseLayout from '../layouts/Base.astro';
import { Image } from 'astro:assets';

interface Props {
  title: string;
  publishYear?: number;
}

const { title, publishYear = 2026 } = Astro.props;
---

<!-- 2. COMPONENT TEMPLATE (HTML thuần túy được xuất ra) -->
<article class="card">
  <h3>{title}</h3>
  <span>Năm: {publishYear}</span>
  <slot /> <!-- Điểm chèn nội dung con (giống children trong React) -->
</article>

<style>
  /* CSS này được Astro TỰ ĐỘNG SCOPE riêng cho component này */
  .card {
    border: 1px solid var(--border);
    padding: 1rem;
  }
</style>

Điểm cốt tử cần nhớ: Biến khai báo trong khối --- là mã tĩnh lúc build. Trình duyệt không thể chạy lại các biến này. Vì vậy, không dùng các hàm sự kiện client như onClick trực tiếp trong template của Astro.

2. File-Based Routing & Dynamic Paths

Astro sử dụng cơ chế định tuyến dựa trên tên file trong thư mục src/pages/:

  • src/pages/index.astro → Trang chủ (/).
  • src/pages/404.astro → Trang lỗi không tìm thấy (/404).
  • src/pages/projects/[slug].astro → Trang động chi tiết từng dự án (/projects/du-an-a, /projects/du-an-b).

Với các trang tĩnh có tham số động (dynamic routes), hàm getStaticPaths() thông báo cho Astro biết tất cả các URL cần được tạo trước:

---
export async function getStaticPaths() {
  const projects = await getCollection('projects');
  return projects.map(entry => ({
    params: { slug: entry.id },
    props: { entry },
  }));
}

const { entry } = Astro.props;
const { Content } = await render(entry);
---
<h1>{entry.data.title}</h1>
<Content />

3. Content Collections: Trái Tim Quản Lý Nội Dung Dự Án

Trong các dự án thông thường, dev hay để file Markdown rải rác và dùng các hàm đọc file tự do. Astro chuẩn hóa việc này bằng Content Collections (định nghĩa tại src/content.config.ts):

import { defineCollection } from 'astro:content';
import { glob } from 'astro/loaders';
import { z } from 'astro/zod';

const projects = defineCollection({
  loader: glob({ pattern: '**/*.md', base: './src/content/projects' }),
  schema: ({ image }) => z.object({
    title: z.string(),
    summary: z.string(),
    cover: image(), // Tự động xác thực và tối ưu file ảnh
    tags: z.array(z.string()),
    order: z.number(),
    live: z.string().url().optional(),
    repo: z.string().url().optional(),
  }),
});

export const collections = { projects };

Lợi ích kiến trúc tối cao:

  • An toàn kiểu dữ liệu (Type-safety): Nếu bạn hoặc AI Agent thêm một file Markdown thiếu trường title hoặc sai đường dẫn ảnh cover, trình biên dịch Astro sẽ báo lỗi ngay lập tức lúc build.
  • Bộ tối ưu ảnh tự động (astro:assets): Bằng cách dùng image() trong schema, ảnh cover của bạn tự động được resize, chuyển đổi thành định dạng hiện đại (WebP) và thêm sẵn thuộc tính width/height chống hiện tượng giật layout (CLS).

4. Nguyên Tắc Điều Khiển Agent Cho Module Này

Chỉ thị cho AI Agent:
1. "Không được cài thư viện quản lý state hay router ngoài (như React Router, Redux). Dùng 100% file-based routing của Astro."
2. "Mọi dữ liệu case study phải đặt trong src/content/projects/*.md và tuân thủ schema Zod đã định nghĩa trong content.config.ts."
3. "Mọi hình ảnh dự án phải hiển thị bằng component <Image /> từ astro:assets, tuyệt đối không dùng thẻ <img> trần."

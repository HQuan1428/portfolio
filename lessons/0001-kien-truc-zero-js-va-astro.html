Kiến Trúc Zero-JS & Vì Sao Lại Là Astro Cho Portfolio?

Nắm vững mô hình tư duy Static Site Generation (SSG), triết lý Zero-JS và lý do Astro vượt trội hơn Next.js đối với một trang web hướng nội dung.

Gắn liền với Sứ mệnh: Để xây dựng một website portfolio đạt điểm hiệu năng tuyệt đối (Core Web Vitals) và giao diện gọn gàng, chúng ta cần hiểu rõ từng kilobyte mã nguồn gửi tới trình duyệt phục vụ mục đích gì.

1. Ba Thế Hệ Kiến Trúc Web

Trước khi đi sâu vào Astro, hãy nhìn lại cách các trang web hiển thị nội dung trên trình duyệt:

Mô hình Cách hoạt động Vấn đề đối với Portfolio
1. Plain HTML/CSS
(Truyền thống)		 Viết từng file .html thủ công. Tải cực nhanh, 0 KB JavaScript thừa. Lặp lại code header/footer ở mọi file; không có hệ thống quản lý bài viết/dự án dạng module hay tự động nén ảnh.
2. SPA / React / Next.js
(Giai đoạn 2018–2024)		 Gửi file HTML rỗng hoặc sơ bộ cùng một gói JS lớn (bundle). Trình duyệt tải JS về để "hydrate" và dựng trang. Nặng nề không cần thiết. Người đọc chỉ xem bài viết nhưng điện thoại phải tốn pin giải nén hàng trăm KB mã React runtime.
3. Astro (SSG + Islands)
(Hiện đại)		 Dùng cú pháp component để lập trình, nhưng tại thời điểm build (build time), toàn bộ component được biên dịch ra HTML/CSS thuần túy. Vừa có trải nghiệm lập trình component tiện lợi như React, vừa xuất xưởng HTML nhẹ tênh như web truyền thống.

2. Triết Lý "Zero JavaScript by Default"

Hầu hết các framework hiện đại (như Next.js hay Nuxt) coi JavaScript là trung tâm: ngay cả khi bạn chỉ viết một trang tĩnh, trình duyệt vẫn phải tải toàn bộ thư viện React/Vue để trang hoạt động.

Astro đảo ngược hoàn toàn tư duy này: Mặc định, không có một dòng JavaScript nào được gửi xuống trình duyệt!

Mã Astro được phân tách bởi rào chắn dấu ba gạch (---), gọi là Component Script:

---
// Khối này CHỈ CHẠY TRÊN MÁY BẠN LÚC BUILD (Node.js/Rust)
// Trình duyệt KHÔNG BAO GIỜ nhìn thấy đoạn mã này!
const projectTitle = "Portfolio Hiện Đại";
const date = new Date().getFullYear();
---

<!-- Phần này được xuất ra thành HTML nguyên bản 100% -->
<header>
  <h1>{projectTitle}</h1>
  <p>Bản quyền © {date}</p>
</header>

Khi chạy lệnh astro build, Astro tính toán giá trị của biến và xuất ra HTML cuối cùng:

<header>
  <h1>Portfolio Hiện Đại</h1>
  <p>Bản quyền © 2026</p>
</header>

Trình duyệt nhận được file HTML nguyên chất này, hiển thị ngay lập tức mà không cần chờ tải hay giải nén bất kỳ framework runtime nào.

3. So Sánh Trực Diện: Astro vs Next.js Cho Portfolio

Next.js cũng có chế độ xuất tĩnh (output: 'export'). Vậy tại sao tài liệu nghiên cứu của dự án lại chọn Astro 7?

  • Không có Hydration Overhead: Next.js tĩnh vẫn phải tải toàn bộ React runtime (khoảng 70–100 kB JS tối thiểu) để xử lý định tuyến phía client. Astro ship 0 KB JS.
  • Tự Động Tối Ưu Hóa Ảnh: Khi dùng static export, Next.js vô hiệu hóa bộ tối ưu ảnh mặc định (bắt buộc dùng dịch vụ ngoài như Cloudinary). Ngược lại, Astro có sẵn astro:assets tự động chuyển đổi ảnh sang WebP/AVIF và tính toán kích thước chiều rộng/cao để triệt tiêu hiện tượng giật trang (CLS).
  • Content Collections: Astro có sẵn công cụ quản lý nội dung Markdown/MDX với bộ kiểm tra kiểu dữ liệu Zod (kiểm tra bài viết có đủ ảnh cover, ngày đăng, tags hay không ngay khi gõ phím).

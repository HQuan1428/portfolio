Cẩm Nang Điều Khiển AI Agent Trong Project Này

Bí quyết thiết lập hàng rào kỹ thuật, ngăn chặn tình trạng phình to mã nguồn và ra lệnh chính xác để AI Agent code chuẩn kiến trúc tối giản theo ý bạn 100%.

Bản chất vấn đề: AI Agent được đào tạo trên dữ liệu của hàng triệu dự án phổ thông, nơi người ta thường xuyên lạm dụng React, Tailwind và các thư viện JavaScript cồng kềnh. Nếu bạn không kiểm soát chặt, Agent sẽ vô thức biến dự án của bạn thành một mớ mã nguồn cồng kềnh!

1. Ba Thói Quen Xấu Thường Gặp Của AI Agent

Thói quen xấu của Agent Hậu quả cho dự án Cách bạn chặn đứng ngay từ đầu
Tự ý cài thêm thư viện
(Tailwind, Lucide icons, Framer Motion, Axios)		 Làm phình file package.json, tăng thời gian build và phát sinh xung đột phiên bản. Đặt quy tắc cấm rõ ràng: "Không cài bất kỳ npm package nào ngoài danh mục đã định nghĩa."
Biến mọi thứ thành React Component Phá vỡ kiến trúc Zero-JS của Astro; gửi hàng chục KB JavaScript xuống client để hydrate. Ép buộc Agent: "Chỉ được viết file .astro thuần túy, không tạo component .jsx/.tsx."
Animate các thuộc tính làm giật layout
(Thay đổi height, width, top, margin)		 Kích hoạt quá trình reflow liên tục của trình duyệt, làm tụt FPS và tăng điểm lỗi CLS. Quy định khắt khe: "Chỉ được phép animate opacity và translate."

2. Bộ Quy Tắc Vàng (Guardrails) Khi Giao Nhiệm Vụ Cho Agent

Khi bắt đầu một phiên làm việc hoặc giao một task mới, bạn hãy đính kèm bộ quy tắc sau vào prompt của mình:

Bộ Hàng Rào Kỹ Thuật (Copy & Paste cho Agent):
1. MÔ HÌNH: Dự án chạy Astro 7 ở chế độ static (0 KB JS mặc định). Không dùng client-side hydration trừ khi có yêu cầu đặc biệt.
2. STYLING: Plain Modern CSS với CSS Nesting và Scoped Styles trong <style>. Không cài Tailwind. Mọi mã màu dùng light-dark() và biến token trong global.css.
3. ANIMATION: 100% CSS Native (@starting-style, @view-transition, animation-timeline). Không cài GSAP hay Motion.
4. DATA: Mọi case study phải nằm trong src/content/projects/ và tuân thủ schema Zod trong content.config.ts.
5. ACCESSIBILITY: Mọi hình ảnh dùng component <Image />, nút bấm ≥ 24px, focus outline rõ ràng.

3. Các Mẫu Câu Lệnh (Prompt Templates) Chuẩn Mực

Mẫu 1: Yêu cầu tạo Component mới (Ví dụ: Card hiển thị dự án)

Hãy tạo cho tôi component ProjectCard.astro tại thư mục src/components/:
- Nhận props gồm dữ liệu của một project entry từ Content Collections.
- Sử dụng component <Image /> từ 'astro:assets' để hiển thị cover.
- Thêm thuộc tính style="view-transition-name: cover-${entry.id}" trên ảnh.
- Toàn bộ CSS viết trong thẻ <style> của component, dùng CSS Nesting và token màu trong global.css.
- Hiệu ứng hover chỉ thay đổi translate: 0 -2px, không dùng JS.

Mẫu 2: Yêu cầu thêm Case Study mới vào Markdown

Hãy viết một bài case study mới tại src/content/projects/he-thong-thanh-toan.md:
- Đảm bảo frontmatter chứa đầy đủ: title, summary, cover, tags, order, repo, live theo đúng schema Zod trong src/content.config.ts.
- Nội dung bài viết tuân thủ cấu trúc 4 phần:
  1. Problem (Vấn đề cần giải quyết)
  2. Role & Constraints (Vai trò & Ràng buộc kỹ thuật)
  3. Solution (Giải pháp kỹ thuật chi tiết)
  4. Outcome (Kết quả định lượng đạt được)

4. Phương Pháp Thẩm Định Nhanh Code Do Agent Tạo Ra

Sau khi Agent hoàn thành một tác vụ, hãy dùng 3 câu hỏi kiểm tra nhanh này:

  1. Kiểm tra git diff package.json: Có dòng dependency nào mới xuất hiện mà bạn không cho phép không? Nếu có → bắt Agent rollback ngay lập tức.
  2. Kiểm tra file build: Chạy npm run build. Xem thư mục dist/_astro/ có xuất hiện file .js lạ nào không? Đối với các trang thông thường, con số phải là 0 file JS.
  3. Kiểm tra CSS: Liệu Agent có tự ý hardcode mã màu như color: #333 thay vì dùng biến token var(--fg) hay không?

5. Bài Tập Củng Cố Nhận Thức (Retrieval Practice)

Kiểm Tra Nhanh
1. Khi muốn ra lệnh cho AI Agent tạo hiệu ứng, mệnh lệnh nào sau đây là chuẩn mực nhất?
2. Bước kiểm tra nhanh hiệu quả nhất để phát hiện AI Agent có làm phình to dự án hay không là gì?
